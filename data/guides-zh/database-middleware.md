实现读副本模式通常有两种常见方式：

1. 将路由逻辑嵌入到应用代码中（上一篇文章已介绍）。
2. 使用数据库中间件。

本文重点介绍第 2 种方式。中间件在应用程序与数据库服务器之间提供透明路由。我们可以基于用户、schema、语句等复杂规则自定义路由逻辑。

上图展示了整体架构：

1. 当 Alice 在亚马逊下单时，请求被发送到订单服务（Order Service）。
2. 订单服务并不直接与数据库交互，而是将数据库查询发送给数据库中间件。
3. 数据库中间件将写操作路由到主数据库，数据随后复制到两个副本。
4. Alice 查看订单详情（读操作）。请求经由中间件发送。
5. Alice 查看最近的订单历史（读操作）。请求同样经由中间件发送。

数据库中间件充当应用程序与数据库之间的代理，使用标准的 MySQL 网络协议进行通信。

## 优点

* 简化应用代码。应用程序无需感知数据库拓扑，也不需要直接管理对数据库的访问。
* 更好的兼容性。中间件使用 MySQL 网络协议，任何兼容 MySQL 的客户端都可以轻松连接中间件，这让数据库迁移变得更加容易。

## 缺点

* 系统复杂度增加。数据库中间件本身是一个复杂的系统。由于所有数据库查询都要经过中间件，通常需要高可用部署来避免单点故障。
* 额外的中间件层意味着额外的网络延迟。因此，这一层必须具备出色的性能。
