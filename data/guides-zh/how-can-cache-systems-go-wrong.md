上图展示了缓存可能出问题的 4 种典型情况及其解决方案。

## 1. 缓存雪崩（惊群问题）

当缓存中的大量 key 同时过期时就会出现这种情况。此时查询请求会直接打到数据库上，导致数据库过载。

有两种方法可以缓解这个问题：一种是避免为 key 设置相同的过期时间，在配置中加一个随机数；另一种是只允许核心业务数据访问数据库，在缓存恢复之前阻止非核心数据访问数据库。

## 2. 缓存穿透

当 key 在缓存和数据库中都不存在时就会出现这种情况。应用无法从数据库中检索相关数据来更新缓存。这个问题会给缓存和数据库都带来很大压力。

要解决这个问题，有两个建议：
*   为不存在的 key 缓存一个空值，避免打到数据库。
*   使用布隆过滤器先检查 key 是否存在，如果 key 不存在，就可以避免访问数据库。

## 3. 缓存击穿（热点 key 失效）

这与惊群问题类似。它发生在某个热点 key 过期时，大量请求会打到数据库上。

由于热点 key 承担了 80% 的查询量，我们不为它们设置过期时间。

## 4. 缓存宕机

当缓存服务宕机、所有请求都涌向数据库时就会出现这种情况。

有两种方法可以解决这个问题：
*   设置熔断器，当缓存宕机时，应用服务既无法访问缓存也无法访问数据库。
*   为缓存搭建集群，提高缓存的可用性。
