在 API 设计中，分页对于高效处理大型数据集和提升性能至关重要。以下是六种常见的分页技术：

*   **基于偏移量的分页：**

    这种技术使用 offset（偏移量）和 limit（数量限制）参数来定义起始位置和要返回的记录数。

    *   示例：GET /orders?offset=0&limit=3
    *   优点：实现和理解都很简单。
    *   缺点：对于较大的偏移量可能变得低效，因为它需要扫描并跳过行。
*   **基于游标的分页：**

    这种技术使用游标（一个唯一标识符）来标记数据集中的位置。通常，游标是一个指向特定记录的编码字符串。

    *   示例：GET /orders?cursor=xxx
    *   优点：对大型数据集更高效，因为它不需要扫描被跳过的记录。
    *   缺点：实现和理解稍复杂。
*   **基于页码的分页：**

    这种技术指定页码和每页的大小。

    *   示例：GET /items?page=2&size=3
    *   优点：易于实现和使用。
    *   缺点：对于较大的页码，存在与基于偏移量的分页类似的性能问题。
*   **基于键集的分页：**

    这种技术使用一个键来过滤数据集，通常是主键或另一个已建立索引的列。

    *   示例：GET /items?after\_id=102&limit=3
    *   优点：对大型数据集高效，并避免了较大偏移量带来的性能问题。
    *   缺点：需要一个唯一且已建立索引的键，实现起来可能较复杂。
*   **基于时间的分页：**

    这种技术使用时间戳或日期来对记录进行分页。

    *   示例：GET /items?start\_time=xxx&end\_time=yyy
    *   优点：适用于按时间排序的数据集，如果添加了新记录，也能确保不会遗漏任何记录。
    *   缺点：需要一个可靠且一致的时间戳。
*   **混合分页：**

    这种技术结合多种分页技术以发挥各自的优势。

    *   示例：结合游标和基于时间的分页，以高效滚动浏览按时间排序的记录。
    *   示例：GET /items?cursor=abc&start\_time=xxx&end\_time=yyy
    *   优点：对于复杂数据集，可以提供最佳性能和灵活性。
    *   缺点：实现更复杂，需要精心设计。
