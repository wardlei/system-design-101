实现读副本模式有两种常见方式：

*   将路由逻辑嵌入应用代码中（在上一篇文章中已说明）。
*   使用数据库中间件。

这里我们重点讨论方案 2。中间件在应用与数据库服务器之间提供透明的路由。我们可以基于用户、schema、语句等复杂规则自定义路由逻辑。

上图展示了这一设置：

1. 当 Alice 在 Amazon 下单时，请求被发送到订单服务（Order Service）。
2. 订单服务不直接与数据库交互。相反，它将数据库查询发送给数据库中间件。
3. 数据库中间件将写入路由到主数据库。数据被复制到两个副本。
4. Alice 查看订单详情（读）。请求通过中间件发送。
5. Alice 查看最近的订单历史（读）。请求通过中间件发送。

数据库中间件充当应用与数据库之间的代理。它使用标准 MySQL 网络协议进行通信。

## 优点

*   简化应用代码。应用无需了解数据库拓扑，也无需直接管理对数据库的访问。

*   更好的兼容性。中间件使用 MySQL 网络协议，任何兼容 MySQL 的客户端都可以轻松连接到中间件。这让数据库迁移变得更加容易。

## 缺点

*   系统复杂度增加。数据库中间件是一个复杂的系统。由于所有数据库查询都经过中间件，它通常需要高可用配置，以避免单点故障。

*   额外的中间件层意味着额外的网络延迟。因此，这一层需要出色的性能。
